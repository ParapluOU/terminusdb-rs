# WOQL query-proof coverage and soundness boundary

This matrix classifies the complete `woql2::Query` enum against the intrinsic
PF4 proof stack. “Transparent” never means “discard the syntax”: public query
identity, projection, routing, and result metadata remain bound into the WOQL
envelope digest. An operator is accepted only when its complete result can be
authenticated.

## A. Semantics-preserving compiler wrappers

| Construct | Status | Soundness condition |
|---|---|---|
| `Select` | Implemented | The proof authenticates the complete BGP; delivered rows must exactly match the selected columns and declared order. |
| `Using` | Implemented; running-node integration covered | Collection identity is in the query digest, and the running node proves/verifies against the exact transaction layer selected by the executed `Using` context. Envelope reuse under another collection string rejects. App/domain callers remain responsible for resolving their declared collection to the supplied immutable layer. |
| `From(instance)` | Implemented | Schema and wildcard graph reads reject. |
| `Pin`, `Immediately` | Implemented | They affect execution/optimization timing, not the declarative BGP result. Their query identity remains bound. |
| `Distinct` | Full-schema transparent; projected form implemented beneath `Count` for one or two exact nonnullable Store-ID witnesses | Full natural-join assignments over set-valued triples are already unique. For the bounded projected form, every public witness tuple defines an exact equality-compacted child class. Unique nonempty tuples plus the sum of class cardinalities equaling the child bag cardinality prove every equivalence class exactly once, with no omissions, extras, or duplicate output tuples. This composes over recursively proved children, including duplicate-producing `Or` and authenticated order. The result remains hidden beneath `Count` because leading SWI `distinct/2` emits the first generated solution of each variant-equality witness class, and that first-occurrence order is not yet authenticated. Unknown/mixed domains, nullable Prolog-unbound witnesses, nested `Distinct`, more than two witnesses, inner `Select`, and visible projected results reject closed. |
| `Comment`, `True` inside `And` | Implemented in woql2 | They add no bindings and do not change conjunction solutions. This TerminusDB fork's JSON parser does not expose query-level `True`; running-node coverage therefore cannot claim it. |
| `Count` | Implemented | The authenticated complete result length is the count. The ordinary executor must deliver exactly the declared count variable and one nonnegative `u64` value. |
| Fully-ground `Triple`/`Link`/`Data` and all-ground `And` | Implemented in woql2; this TerminusDB fork's JSON parser exposes only `Triple` | Each Store UNIT filter authenticates a zero-arity existence bit; an all-ground conjunction returns their verified boolean AND, preserving duplicate-atom idempotence. If a standalone term is dictionary-absent, the verifier recommits the root-bound clear catalog and authenticates the empty relation. |
| Ground atoms mixed with variable-bearing atoms | Implemented | Variable-bearing atoms form the authenticated relational prefix; verified ground UNIT bits gate its complete result. A false gate forces the same output arity to canonical zero commitments at the verifier-derived result domain and forces result length zero. |
| Dictionary absence in any constant-bearing atom | Implemented recursively | The verifier recommits the root-bound clear predicate and node/value catalogs, authenticates the first absent `(atom index, position)` claim, and requires the complete relation to have zero length with canonical zero commitments at its exact public arity. Empty leaves compose through joins, `Or`, `Not`, and `Optional`; node IRIs and aligned typed literals are covered. |
| Disconnected BGP/cartesian product | Implemented | Each disconnected step joins verifier-derived UNIT columns through the complete binary-join argument, proving every source-index pair exactly once. UNIT relocations bind both sides, the synthetic output key is checked and removed, and schema order remains accumulator variables followed by the new component. |
| Compatible-schema `Or` | Implemented recursively | Every branch is an independently proven read relation against the same trusted root. Branches may themselves be BGP, bag union, `Not`, or `Optional`; nested unions flatten in source order and preserve exact bag multiplicity. Schema reorder mappings, branch order, descriptors, routing, and outer projection/count metadata are digest-bound. Branch-local `Select`/`Count`/`Distinct`, conflicting routing, and incompatible schemas reject. |
| `Not` | Implemented recursively | Global `Not` is authenticated by right-side nonemptiness. Correlated `Not` is an exact one- or two-key left anti-join over any already-proved read relation, including `Or`; top-level `Not` and `Optional` operators fold in source order after the positive relation. Correlation through a nullable outer column rejects because an unbound Prolog variable is bindable and cannot soundly be modeled as SQL null equality between independent children. |
| `Optional` | Implemented recursively | Global and one-/two-key correlated left outer joins accept any already-proved non-ground read relation, including `Or`, and authenticate exactly one null-extended row per unmatched left row. Top-level optionals may mix sequentially with `Not` when every later correlation key is nonnullable. Nullable-key correlation rejects for the same Prolog-unbound reason as `Not`. |
| Bounded `When` | Implemented recursively, including existential branch locals hidden by `Select`/`Count` | Leading Prolog compiles `when(A,B)` as `((A,B);true)`. For an already-proved outer relation, the proof authenticates `bag_union(project_outer(inner_join(inner_join(outer,A),B)), outer)`: every successful local assignment retains exact bag multiplicity after projection, and the `true` branch emits every incoming assignment once even when `A` fails. This is deliberately not a left outer join. `A` and `B` must each share one or two nonnullable namespace-compatible variables with their input relation and may introduce branch-local variables, including a consequent correlated through a condition local. Locals are accepted only when enclosing `Select` chains omit them or `Count` hides all rows, and they may not be referenced by a later operator. Exact bag projection reuses a unique subset/reordering of child commitments with unchanged rows, domain, order, and multiplicity. The `/when` digest wrapper distinguishes this syntax from explicit union/join/projection composition. Top-level `When`, visible/escaping locals, later local reuse, nullable correlations, result-wrapped subplans, routing conflicts, and more than two correlation variables reject closed. |
| Predicate variables | Implemented | Predicate IDs are authenticated in their independent dictionary namespace, remain public result columns, compose through joins/operators, and resolve only through the predicate catalog. Cross-namespace variable reuse rejects. |
| `Link` and `Data` | Implemented in the canonical woql2 proof AST | Constants intrinsically authenticate their kind. Variable `Link` and `Data` carry an explicit transcript- and wire-bound `Node`/`Literal` object-kind filter. The Store authenticates the reserved node datatype tag against the root-bound node/value dictionary; `Data` proves its exact `chi_real - node_selector` complement, preserving original Store IDs across mixed literal datatypes. Empty/all-node results, predicate variables, joins, wire versioning, and kind substitution are covered. A supported numeric comparison on `Data` subsumes the broad literal filter by proving one exact literal datatype; comparison on `Link` rejects closed. The current leading TerminusDB JSON parser does not expose either variant. |
| Exact relational `Equals` | Implemented recursively for already-bound operands | An IsZero selection plus exact LogUp compaction filters a complete authenticated input relation. Node-only, predicate-only, or identical exact-datatype nonnullable columns are accepted; operand order, column indices, exact domains, and canonical constants are digest-bound. Free-variable assignment, nullable operands, unknown mixed node/value columns, predicate↔node/value comparisons, lists/dictionaries, and cross-datatype numeric coercion reject. Constant/constant equality is an authenticated true/false relation gate under the same exact-type rule. |
| Zero-/one-/two-node-key `GroupBy` immediately consumed by `RangeMin`/`RangeMax` | Implemented recursively for exact fixed-width integral values | Accepts zero to two unique nonnullable node-IRI keys, a child-bound UInt8/16/32/64 or Int8/16/32/64 template, one private grouped-list variable, and an adjacent forward extrema consumer. Key tuples are resolved through the root-authenticated catalog and sorted lexicographically by canonical expanded-IRI UTF-8 bytes in declared `group_by` priority, never child schema order or Store ID. This matches leading SWI `bagof` term order across child layers. Duplicate child rows and equal values retain multiplicity internally; strict comparison makes equal extrema first-wins, while the public output retains the original typed Store ID. Zero-key grouping emits one extremum iff the child is nonempty and no row for empty input. Output is declared keys followed by the extremum. Store wire/digest bind key mapping, datatype, kind, and child; key-order, datatype, kind, aggregate-family, and recommitted result tamper reject. Existing arbitrary scalar one-key plans are intentionally no longer accepted: keys must be exact nodes. Float/Boolean/coercive or variable-width values, numeric/predicate/nullable keys, more than two keys, visible lists, reversed/non-immediate consumers, and arbitrary list extrema reject closed. Outer `Select`/`Count` and recursive children compose. |
| Zero-/one-/two-node-key `GroupBy` immediately consumed by `Sum` | Implemented recursively for UInt8/Int8 through UInt64/Int64 templates, including bounded-i64 `xsd:integer` | Accepts zero, one, or two distinct nonnullable node-IRI keys, one exact fixed-width integral Store-value template, a private grouped-list variable consumed immediately and once by `Sum`, and a distinct output variable. The ordered key-to-child-column mapping is bound by both WOQL and Store plan digests. Zero-key SWI `bagof` produces one bag iff the child has a solution, so the proof emits exactly one generated sum row for nonempty input and no row for empty input—never a fake UNIT key. Keyed child rows are grouped by tuples of root-catalog canonical expanded-IRI bytes in the declared `group_by` priority order, matching SWI tuple order even when that order differs from child schema order and child-layer Store IDs append out of lexical order. Output arity is respectively one, two, or three columns: declared keys followed by the generated sum. Every public child value ID is independently resolved by the verifier through the root-bound catalog with its exact datatype and canonical lexical width; signed order-preserving Store bytes are sign-bit-unflipped before arithmetic, and duplicate rows retain multiplicity. Unsigned values use checked `u64` accumulation. Signed values use a bounded-safe `i128` intermediate matching Prolog cancellation semantics and require the final total to fit `i64`; actual overflow rejects. Separate digest- and wire-bound `GeneratedDecimalU64` and `GeneratedDecimalI64` domains prevent signed-bit reinterpretation, and descriptor-driven resolution makes signed zero a real nonnull value. Signed fields are canonically `Fr(v)` or `-Fr(abs(v))`, with the verifier accepting only the exact i64 image. Sequential `Equals`, `Greater`, `Gte`, `Less`, and `Lte` against exact integral `xsd:decimal` constants derive and recommit the complete matching relation; the aggregate datatype selects U64/I64, and operator, operand order, constant, domain, and query identity are bound. Outer `Select`/`Count` and bounded `When` composition remain supported. Fractional/scientific/overflow constants, Store integer tags, wrong variables, and signed/unsigned substitution reject closed. Visible rows, portable envelopes, signed/unsigned executor values, child-stack and declared-key ordering, duplicate/zero/minimum/maximum/cancellation cases, empty input, arity/domain/key-mapping substitution, datatype mismatch, actual overflow, sign tamper, operator/order/query substitution, and filtered-result tamper are covered. More than two keys, duplicate/non-node keys, floating/variable-width values, list leakage/reuse, reversed/non-immediate/standalone `Sum`, constant outputs, and unsupported children reject closed. |
| Zero-/one-/two-node-key `GroupBy` immediately consumed by `Length` | Implemented recursively as exact bag cardinality | Accepts a private grouped list consumed immediately and once by canonical `Length`, with a distinct generated `xsd:decimal` result and zero to two distinct nonnullable node-IRI keys. Leading Prolog compiles this shape to `group_by/4` followed by marshalled `length/2`; list order and element values are unobservable, while duplicate child solutions each contribute one. Global grouping emits one count row iff the child has a solution and no row for empty input. Keyed output follows the same root-catalog canonical expanded-IRI tuple order and declared key priority as grouped sum. The Store and WOQL plans reuse the authenticated grouping contract, bind the ordered key mapping, and emit `GeneratedDecimalU64`; sequential exact integral decimal Eq/Gt/Gte/Lt/Lte filters, outer Select/Count, and bounded When composition reuse the generated-u64 machinery. Constant/list-leaking outputs, missing or nullable templates, duplicate/non-node/more-than-two keys, non-immediate Length, and arbitrary list Length reject closed. |
| `Collect` immediately consumed by `Length` | Implemented recursively as exact collection cardinality | Leading Prolog compiles canonical `Collect(template, into, query)` to `findall/3`, preserving one private list element per child solution including duplicate/identical templates and always succeeding with `[]` for empty input. Immediate canonical `Length(list, length)` exposes only the child solution count: list order, element values, and fresh copies of unbound template variables are unobservable. The wire- and digest-distinct `CollectionCount` plan reuses the shared cardinality derivation with an explicit `emit zero for empty` policy, so it cannot substitute for zero-key GroupBy-Length, which emits no row on empty input. The result is one nonnullable `GeneratedDecimalU64`/`xsd:decimal` row, including zero; exact decimal Eq/Gt/Gte/Lt/Lte filters and outer Select/Count compose. The collected-list and length-result variables must be distinct, the list must be consumed immediately and exactly once, and neither may alias a child binding. Mismatched, leaking, reused, reversed, non-immediate, standalone, or result-wrapped child forms reject closed. |
| `Collect` immediately consumed by `Sum` | Implemented recursively for exact fixed-width integral templates | Accepts either one nonnullable child-bound template variable with an exact UInt8/16/32/64 or Int8/16/32/64 descriptor, or one exact ground constant of those canonical XSD types; bounded-i64 `xsd:integer` maps to Int64. Leading Prolog's `findall/3` retains one typed private value per child solution and `sum_list/2` strips typed wrappers before arithmetic. Duplicate values retain multiplicity and order is unobservable. Empty input produces `[]`, then exactly one typed generated zero row; U64/I64 is selected and bound from the template datatype. Variable templates are independently resolved through the root-authenticated value catalog. Unsigned accumulation checks u64 overflow; signed accumulation uses an i128 intermediate for cancellation and requires the final result to fit i64. The wire- and digest-distinct `CollectionSum` plan binds column-versus-constant mode, exact constant, datatype, and child relation, preventing substitution with Collection-Length or zero-key GroupBy-Sum. Exact decimal comparisons and outer Select/Count compose. Unbound/mixed/nullable, float, decimal/coercive, list/dictionary/node templates; aliases, leaks, reuse, reversed/non-immediate/standalone Sum, and result-wrapped children reject closed. |
| `Collect` immediately consumed by `RangeMin`/`RangeMax` | Implemented recursively for exact fixed-width integral child variables | Leading Prolog compiles `Collect` to `findall/3`, then folds the private list with `woql_less/2`; an empty list fails and produces no result row. The bounded proof accepts an adjacent forward consumer over one nonnullable child-bound UInt8/16/32/64 or Int8/16/32/64 variable. Every candidate ID and exact datatype is independently resolved through the root-authenticated value catalog, comparison uses the Store's order-preserving lexical encoding, and the output retains the selected original typed Store ID. Duplicate equal values preserve Prolog's first-wins result value, which is observationally identical at the Store-ID boundary. The wire- and digest-distinct `CollectionExtrema` plan binds child column, datatype, and Min/Max kind; substitutions and recommitted non-extreme results reject. The private list never appears in the schema. Ground/unbound/mixed/nullable, float, decimal/coercive, node/list templates; aliases, reversed/non-immediate consumers, and result-wrapped children reject closed. Outer Select/Count and recursively proved children compose. |
| Exact scalar `OrderBy` | Implemented recursively for bounded ascending and descending forms | Accepts one direction-bound template naming the complete one-column, nonnullable fixed-width numeric result of any already-proved read relation. Ascending proves the authenticated lookup values directly. Descending derives the padded key commitment `MAX*chi_real-values`; both directions use a transcript-bound nondecreasing sort mode and a full-row multiset permutation. Equal values retain exact bag multiplicity. Because the key is the complete public row, tied occurrences are identical and SWI stable-tie order is observationally irrelevant. Multiple/partial keys, nullable results, unknown or mixed domains, projections, counts, and unsupported children reject closed. |
| Exact complete-row multikey `OrderBy` | Implemented recursively for two or three keys | Every output column must appear exactly once in any priority order, with an exact nonnullable fixed-width numeric datatype and independent Asc/Desc direction; the child may be any already-proved read relation satisfying those exact complete-schema constraints. The priority-ordered key-index permutation is Store-plan, transcript, recursive-envelope, and WOQL-digest bound, while output columns remain in canonical schema order. One full-row multiset permutation preserves multiplicity and tuple correlation. The verifier resolves every public output ID through the root-bound catalog, enforces complete datatype masks, derives OP-value commitments, packs priority-ordered keys injectively at radix `2^64`, and proves nondecreasing 128/192-bit order. Equal packed keys imply identical complete rows, making SWI stable-tie order observationally irrelevant. Nested `Start`/`Limit`/ordered `Once` compose. Partial, duplicate, missing, or out-of-range key mappings, nullable/unknown/mixed types, projections, counts, and unsupported children reject closed. |
| `Start`, `Limit` over authenticated order | Implemented recursively for the bounded ordered form | Leading Prolog compiles these to SWI `offset/2` and `limit/2`, so wrapper nesting is preserved inside-out. The verifier derives the exact contiguous child rows, canonical output length/domain, and commitments from the already-authenticated ordered columns. `Start(0)` is identity, an offset beyond the source is empty, and `Limit(0)` is empty; large `u64` values saturate safely against the source length. Nested slices, empty results, outer routing wrappers, query substitution, and reordered-content rejection are covered. Unordered children and result wrappers reject closed. |
| `Once` over authenticated order | Implemented as an exact one-row ordered slice | Leading Prolog compiles `once(A)` to `once(ProgA)`: it commits to the first generated solution and otherwise returns empty. On an authenticated ordered child this is exactly `offset=0, limit=1`, so it reuses the ordered-slice proof. The WOQL digest uses a distinct `Once` tag, preventing substitution with explicit `Limit(1)`. Nested empty ordered slices are supported; unordered children reject closed. |
| Bounded `TripleSlice`, `TripleSliceRev`, `TripleNext`, `TriplePrevious` | Implemented for constant S/P and zero or one fixed-width numeric object column | Leading Prolog's slices are half-open `[low, high)` typed-object scans in ascending/descending value order. Next/previous select the nearest same-datatype value strictly above/below an arbitrary typed reference and support the object, cursor, or neither as a variable. The proof lowers these exact forms to an authenticated constant-S/P BGP range, complete one-column exact scalar order, and (for cursors) exact `Limit(1)`. A supplied ground result is then constrained by exact typed equality and projected to the canonical hidden UNIT column, returning one zero-column row iff the triple/range or immediate adjacency holds. Store globally merges typed value order across child-layer dictionaries. Default/instance graph, same-type fixed-width constants, reverse binding modes, empty endpoints, exclusive boundaries, missing triples, dictionary absence, and query/direction substitution are covered. Variable S/P/full-triple ties, strings, schema routing, and both-variable cursors reject closed. |
| Explicit instance-graph `TripleCount` and bounded comparisons | Implemented as a root-derived generated `xsd:decimal`-u64 scalar | Leading Prolog's explicit graph form reads the logical visible triple count of that graph. For resources ending in `/instance`, the proof emits exactly one generated scalar derived from the trusted layer root's committed `materialized_count`; it is not interpreted as a Store dictionary ID, and zero remains a real value rather than nullable padding. Sequential `Equals`, `Greater`, `Gte`, `Less`, and `Lte` filters accept that bound count variable against an exact nonnegative integral `xsd:decimal` constant in `0..=u64::MAX`, on either operand side. The verifier derives the exact retained row/empty relation without dictionary lookup or another polynomial argument; operator, operand order, constant, domain, and query identity are bound. Fractional, negative, scientific-exponent, overflow, non-decimal datatype, other-variable, variable/variable, and comparison-before-source forms reject closed rather than claiming general Prolog numeric coercion. Empty and child-layer stacks, zero/maximum boundaries, the canonical explicit decoder, `Select`/outer `Count`, portable envelopes, executor-value matching, wrong resource/root/query metadata, and forged/recommitted output rejection are covered. Graphless database resources, schema graphs, other routed resources, and constant output unification reject closed because their leading-Prolog aggregation/routing semantics are not represented by one supplied instance-layer commitment. |

Write/routing constructs (`Into`, `Add*`, `Delete*`, document mutations) are not
read-query wrappers and remain rejected by query-proof generation.
Recursive plans and envelopes fail closed above depth 64, 4096 relation nodes, or
256 MiB of encoded proof data.

## B. Operators composable from existing proof gadgets

These are tractable without inventing a new polynomial commitment protocol, but
still require authenticated composition and must remain rejected until that
composition is implemented.

| Construct | Existing foundation | Missing composition |
|---|---|---|
| General `OrderBy` and triple navigation beyond the bounded constant-S/P scalar subset | exact bidirectional scalar and bounded complete-row multikey order with authenticated arbitrary complete-key priority mappings; bounded scalar and ground triple navigation are implemented | Address partial-key stable ties and complete physical/logical tie order for visible S/P/full triples. Variable-width string collation and schema routing require their separate exact contracts. |
| Visible projected `Distinct` | exact unordered one-/two-key class partition beneath `Count` | Authenticate SWI's streaming first-occurrence order and the complete first row's non-witness bindings. SWI uses term variance (`=@=`), so nullable/unbound witnesses also need the authenticated Prolog-unbound representation. |
| General unordered `Once` | complete BGP plus count/existence and authenticated selection | Define and authenticate TerminusDB's executor first-solution order. The bounded ordered form above is implemented; unordered first-solution selection remains unsound. |
| General `When` with observable newly introduced variables | bounded existential-local `When`, exact inner joins, bag projection, bag union and nullable result descriptors | Hidden locals are implemented. When a local remains observable, the unconditional `true` branch leaves it Prolog-unbound while successful rows bind it. Extending coverage requires an exact union schema that represents this branch-local unbound value without treating it as ordinary SQL null equality in later correlations. |
| General `GroupBy`, live `Collect`, standalone/coercive `Sum` or `Length` | sumcheck, count, sort, membership, generated scalars and commitments | The bounded grouped extrema, immediate grouped/collected sums, immediate grouped/collected cardinality, and immediate collected extrema forms above are implemented without exposing their private lists. General live `GroupBy` is SWI `bagof` and live `Collect` is `findall`, so both expose ordered Prolog lists. Standalone consumers accept caller-supplied or generated list structures; general `Sum` additionally has broader numeric coercions. A versioned authenticated list contract plus the remaining coercion semantics is required for those broader forms. |
| General `RangeMin`, `RangeMax` | range selection and strict sort | The immediately consumed exact-datatype grouped and collected forms above are implemented. Arbitrary instances consume already-bound lists, fail on empty input, and use coercive `woql_less`; those still require an authenticated list contract and coercion semantics. |
| Additional Store-value scalar ranges | dictionary value lookup and range bit proofs | Fixed-width integers are implemented exactly. The generated-u64 `TripleCount` comparison above is a separate verifier-derived decimal subset, not Store-value coercion. General decimal/arbitrary integer, temporal, string, and independently typed Float32/Float64 families need the representations or circuits listed below. |

## C. Operators needing genuinely new crypto or a new authenticated data model

| Construct family | Why existing gadgets are insufficient |
|---|---|
| Arbitrary `Path` | Requires authenticated transitive closure/regular-path evaluation, not a fixed left-deep relational join. |
| `Eval`, generative/coercive `Equals`, `Typecast`, string/regex/`Like`, collection/set/list operators, `Sequence`, interval/date operators | Need circuits or lookup arguments for their full value semantics and authenticated linkage to output values. |
| `Get` and external resources | Requires an authenticated external-resource commitment and routing model. |
| `ReadDocument` | Requires proof semantics for document reconstruction, field multiplicity, subdocuments and JSON shape over triples. |
| `IsA`, `TypeOf`, `Subsumption` | Require authenticated schema graph selection and transitive schema reasoning. |
| `Size`; `TripleCount` beyond one explicit instance graph | `Size` sums physical `.larch` filesystem bytes and is not committed by the logical layer root. Database-level/schema `TripleCount` requires authenticated multi-graph resource routing and the leading Prolog aggregation contract. |
| `LexicalKey`, `HashKey`, `RandomKey` | Deterministic key functions need value circuits; `RandomKey` is intentionally nondeterministic and cannot be a reproducible proof statement without an explicit randomness transcript. |
| Named-query `Call` | Requires authenticated query-definition lookup, parameter substitution, and recursion termination semantics before compiling the expanded statement. |

All unlisted `Query` variants fall into their corresponding family above and
fail closed today. No query path schedules proof generation, and this matrix
makes no GPU or proof-lifecycle policy choice.

## Exact scalar datatype boundary

Range filters, exact scalar/complete-row ordering, and bounded grouped extrema use the
same Store-routed constant encoding and require identical datatypes. They do not emulate
Prolog's numeric cross-type coercions.

| WOQL/XSD value | Store proof datatype | Status |
|---|---|---|
| `xsd:boolean` | `Boolean` | Exact |
| `xsd:unsignedByte`, `xsd:byte` | `UInt8`, `Int8` | Exact |
| `xsd:unsignedShort`, `xsd:short` | `UInt16`, `Int16` | Exact |
| `xsd:unsignedInt`, `xsd:int` | `UInt32`, `Int32` | Exact; `UnsignedInt(usize)` is bounds-checked to u32 |
| `xsd:unsignedLong`, `xsd:long` | `UInt64`, `Int64` | Exact |
| `xsd:integer` | `Int64` | Exact only for the AST's explicitly bounded i64 subset; canonical values outside i64 reject during decoding |
| current `Float(f64)` AST value | `Float64` | Exact same-type finite-value range support; the AST currently conflates `xsd:float` and `xsd:double` |
| `xsd:decimal`, arbitrary-precision `xsd:integer` | variable/arbitrary width | Blocked on a bounded public representation and exact Prolog numeric/coercion semantics |
| `xsd:dateTime`, `xsd:time` | variable width | Blocked on a canonical ordered proof representation matching leading Prolog |
| `xsd:date` | 12-byte Store lexical value | Blocked by the current single-u64 order-preserving range contract and timezone semantics |
| strings and string-derived types | variable width | Blocked on authenticated byte/string collation matching Prolog structural comparison |

The explicit schema decoder bounds-checks every fixed-width typed JSON value. Planner and
Store tests cover signed minima, zero, maxima, unsigned maxima, distinct-datatype rejection,
both order directions, and a real `Int8` dictionary/range prove-and-verify round.

The cross-repository implementation checkpoint, hardware commands, macOS path,
and ordered continuation plan are recorded in
[`WOQL_QUERY_PROOF_GPU_HANDOFF.md`](WOQL_QUERY_PROOF_GPU_HANDOFF.md).
